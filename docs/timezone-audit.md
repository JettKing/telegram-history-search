# 时区影响审计

## 结论

系统数据库使用 SQLite `CURRENT_TIMESTAMP` 保存 UTC 时间。API 返回原始数据库值，前端负责按 `Asia/Shanghai` 显示。采集器现在会将 Telethon 的消息时间统一序列化为带 `Z` 的 UTC ISO 8601 字符串，避免无时区时间被错误解释。

## 已检查项目

| 项目 | 结果 | 处理方式 |
|---|---|---|
| 管理员会话过期时间 | 曾存在前端直接解析风险 | 使用统一 UTC 解析并显示北京时间 |
| 授权码到期与最近使用时间 | 数据库为 UTC | 展示层转换为北京时间 |
| 频道最后同步时间 | 数据库为 UTC | 展示层转换为北京时间 |
| 采集任务开始/结束时间 | 数据库为 UTC | 展示层转换为北京时间 |
| 审计日志时间 | 数据库为 UTC | 展示层转换为北京时间 |
| Telegram 消息发布时间 | Telethon 时间可能为 naive/aware datetime | 采集器强制规范为 UTC、带 `Z` 的 ISO 8601 |
| GitHub Actions 定时任务 | cron 使用 UTC | 当前每 30 分钟执行一次，不受日历时区影响 |
| 授权码过期判断 | SQL 使用 `CURRENT_TIMESTAMP` | 保持 UTC 与数据库时钟一致 |

## 注意事项

GitHub Actions 的 cron 表达式使用 UTC。当前 `*/30 * * * *` 表示每小时的第 0 分和第 30 分执行，不需要转换为北京时间。如果以后改为每天固定时间，应按 UTC 编写；例如北京时间每天 08:00 应写为 UTC 00:00。
